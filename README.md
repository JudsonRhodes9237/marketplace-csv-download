# Return a CSV download link from your marketplace backend

```bash
export INFRAI_API_KEY="your-key"
PYTHONPATH=src python3 -m marketplace_export examples/orders.json
```

The command turns marketplace rows into a real CSV, uploads it, and prints JSON with `export_key`, `download_url`, and `expires_seconds`. Your product can return `download_url` from a report route exactly as a Next.js route would return a signed URL to the browser.

Infrai keeps this flow behind one API key: the backend creates the storage bucket, signs the upload, and signs the download without adding a storage SDK to the app. The example uses plain REST so the Python worker can sit beside a Next.js storefront without introducing a second client library.

## Run the export path

Use Python 3.10 or newer. The repository has no third-party packages.

```bash
export INFRAI_API_KEY="your-key"
PYTHONPATH=src python3 -m marketplace_export \
  examples/orders.json \
  --bucket marketplace-exports \
  --expires-seconds 900
```

Bucket creation is an explicit startup step in the workflow. The command then asks `POST /v1/storage/object/presign/{bucket}/{key}` for a PUT URL, uploads the generated bytes to that URL, and asks the same endpoint for a GET URL with an attachment filename. The returned link lasts for the requested window; the stored CSV remains private.

The input is a JSON array. Each object becomes one row, and the keys from the first object become the header:

```json
[
  {"order_id": "ord_1042", "product": "Canvas tote", "quantity": 2}
]
```

## Drop it behind a product route

`publish_marketplace_export` is the application boundary. Pass it the rows already authorized for the signed-in seller, then serialize its result from your route handler. The content hash gives repeated exports of the same rows the same object key and idempotency keys, which makes retries predictable.

The one real gotcha is placement: `bucket` and `key` belong in the presign URL path. The JSON body contains `op`, `expires_seconds`, and the signing options. Keeping that split inside `InfraiClient.storage_object_presign` makes the route-level code hard to misuse.

This sample intentionally stops at export publication. Authentication, seller access checks, background-job status, and link delivery belong to the marketplace application around it.

## Check the behavior locally

The focused tests use a recording client, so they do not make network calls. They verify CSV quoting and the create, PUT-sign, upload, GET-sign sequence.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```
